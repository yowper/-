# 手机助手（volumeswipe）

**一个用语音控制视频 App 的 Android 无障碍小工具。** 说一句话，它帮你暂停/播放、翻下一集、跳过广告、调音量、调亮度、打开 App。

不用 root，不用连电脑，**只需要打开无障碍服务**。

| | |
|---|---|
| 应用名 | 手机助手 |
| 包名 | `com.example.volumeswipe` |
| 版本 | 2.14（versionCode 34） |
| 系统 | Android 7.0+（minSdk 24），targetSdk 34 |
| 架构 | **只含 arm64-v8a**（近几年的手机都是，老 32 位机装不上） |
| 体积 | 约 56 MB（里面打包了 65 MB 的中文语音识别模型 + 11 MB OCR 引擎） |
| 下载 | https://github.com/yowper/volumeswipe/releases （每个版本一个 APK） |

## 一、装好后按 ①②③④ 走一遍

打开 App，主界面上从上到下就是这四步：

| 步骤 | 按钮 | 作用 |
|---|---|---|
| ① | 允许后台运行（忽略电池优化） | 不点它，MIUI / 鸿蒙 / ColorOS 过一会儿就把服务杀掉 |
| ② | 授予悬浮窗权限 | 屏幕上要显示那条小命令条 |
| ③ | 打开无障碍设置并开启本服务 | **核心**，没这个什么都干不了 |
| ④ | 开启后台常驻服务 | 通知栏出现「手机助手 · 运行中」，进程优先级提到最低 |

另外两个可选：

- **☀ 允许修改系统设置** —— 只有说「亮 / 暗」调屏幕亮度才需要，点它跳到系统页把开关打开。
- **▶ 测试Mic（标定麦克风位置）** —— 如果唤醒后豆包键盘出来了却没开始听，点这个：程序弹出键盘后，你**手点一下键盘上的麦克风按钮**，它就把你点的位置记下来（默认 22%, 66%），以后自动点。

再去系统设置里放行三项（每个 ROM 名字不同，意思一样）：**自启动**、**后台弹出界面 / 后台运行**、**电池无限制**。

## 二、两套识别路线

由主界面那个勾 **「使用豆包语音输入法」**（默认勾选）决定：

### 勾选豆包（推荐）

```
听到「嗨小白」
  → 【什么都不做】：不静音、不在视频上点任何地方
  → 屏幕上弹出输入框 + 立刻弹键盘
  → 自动点一次豆包输入法的麦克风（默认 22%, 66%）
  → 你对着豆包说命令
  → 框里一出现短句（≤6 个中文字）就立刻收尾执行
  → 最长等你设置的秒数（默认 3 秒）
```

也就是**不靠本地语音听命令，命令全交给豆包输入法**——它听得比本地模型准得多。

- 说「打开豆包」＝把设置里这个勾**勾上**（并且立刻叫出豆包键盘让你直接说话）
- 说「关闭豆包」＝把勾**去掉**
- 说「豆包」＝**切换**（勾着就关、没勾就开）
- 说「打开豆包应用」＝启动豆包这个 App（跟上面三个意思不同）

### 不勾选豆包（纯本地）

不用唤醒词，本地语音引擎（Vosk 中文模型，已打进 APK）听整个命令表，听到命令直接执行。

### ⚠️ 两种情况都一样：**不用唤醒词也能下命令**

没听到「嗨小白」时，本地引擎会先自己认一遍——**只要能对上任何命令就直接执行**（只收 8 个字以内的短句，长句当视频里的话不理）。
所以下面这些你**可以直接说，不必先说「嗨小白」**：

```
停    放    下一集    上一集    上页    下页    广告    直播
大    小    亮    暗    抖音    红果    打开豆包    关闭豆包    小白再见
```

## 三、完整命令表

| 你说 | 它做什么 |
|---|---|
| `嗨小白` / `小白` | 唤醒：只弹键盘 + 点一次豆包 Mic，**不动屏幕、不静音**（不和命令组合，后面说的一律不算） |
| `停` `继续` `播放` `继续播放` `暂停` `恢复播放` `接着看` `开始播放` `放着` `放一下` | 同一条命令：**在 (50%,20%) 点一下**（点击时长默认 120ms） |
| `下一集` `下一部` `换一集` `上翻` `下集` `下一级`… | 上滑：(50%,75%) → (50%,25%)，时长默认 300ms |
| `上一集` `上一部` `下翻` `上集` `上一级`… | 下滑：反方向 |
| `广告` `退出广告` `跳过广告` `关掉广告` `跳过这段广告` | 见下方专节：**先截图 → 点 (50%,20%) 暂停 → 读下方读秒 → 上拉前再截图确认没秒了 → 只上拉一次** |
| `直播` `退出直播` `推出直播` | 比「退出广告」多一个动作：**先从屏幕最右边缘往左划**；左划之后的动作和「退出广告」**完全一样**（同一条代码路径）：截图 → 点 (50%,20%) 暂停 → 读秒 → 上拉前再截图确认无秒 → 只上拉一次 |
| `上页` / `下页` | 点 (15%, 85%) / 点 (85%, 85%) |
| `大` `大一点` `声音大` `音量大` `大点声` `调大` | 媒体音量 +1 格 |
| `小` `小一点` `声音小` `音量小` `小点声` `调小` | 媒体音量 −1 格 |
| `禁音` `静音` `关声音` `关闭声音` | **关掉声音**（记住当时的音量；接电话前用，短剧模式里也能用） |
| `声音` `恢复声音` `打开声音` `开声音` | **恢复刚才的音量**（接完电话用，短剧模式里也能用） |
| `亮` `亮一点` `调亮` `变亮` | 屏幕亮度 **+25**（0~255），需要 ☀ 授权 |
| `暗` `暗一点` `调暗` `变暗` | 屏幕亮度 **−25**，需要 ☀ 授权 |
| `抖音` `红果` `番茄` `证券`（`股票`/`炒股`）`ds`（`deepseek`）`天鹅` `阅读` `b站` `快手` `微信`，或 `打开抖音`… | 直接启动对应 App（喊名字就行，不必说「打开」） |
| `豆包` / `打开豆包` / `关闭豆包` | 切换 / 勾上 / 去掉「使用豆包语音输入法」 |
| `短剧` | **切换短剧模式**（没开就进入，开着就退出；模式里只听 下集/上集/广告/直播 和自己录的命令，见第六章） |
| `录制` | **开始录制动作**：直接去做动作（每个动作都会真的执行并被记下来），做完**双击屏幕**结束 → 弹出文本框起个命令名 → 保存（录制中再说「录制」= 结束） |
| `打开豆包应用` | 启动豆包 App |
| `测试读秒` | 弹出读秒探测面板，看当前屏幕下方能不能读到读秒 |
| `小白再见` `再见小白` `小白拜拜` | 彻底退出（清配置、停常驻服务、收窗口） |

### 4.1 只认这份命令表（重要）

**不在上面表里的话，一律不执行，也不在屏幕下方显示**（只写进日志，方便你查它到底听成了什么）。

还额外做了三层收紧：

| 收紧 | 例子 |
|---|---|
| 单字命令（`停` `大` `小` `亮` `暗`）必须**整句就这一个字** | 说 `停` ✓；说 `停下来看看` ✗（不执行） |
| 不再是「≤ 4 字里含亮/暗/大/小 就算」 | 说 `真亮` `好暗啊` `很大` ✗（不执行） |
| 含唤醒词的句子一律不当命令 | `嗨小白下一集` `小白广告` ✗（只当唤醒） |

单字命令**还要有视频/声音在播**才执行（没在播就只听不动作）；
被拦下的都会写进日志，写明拦的原因。

### 4.2 上滑 / 下滑只滑一次（重要）

不管哪条命令，**上滑/下滑都只滑一次，不会连着滑好几次**：

- 滑动类命令（`下一集` `上一集` `广告` `直播`）**3 秒内只滑一次**：
  刚滑过又听到同一类命令 → 只写日志「不再滑第二次」
- 手势层面还有一道硬锁：**两次上滑/下滑至少隔 0.9 秒**（不管是哪条路径叫的，包括摇一摇）
- 广告/退出直播：**上拉前已经截图比较确认无秒了，就只拉这一次**（不再核对、不再补滑）

### 防止识别抖动（自动，不用管）

- 同一条命令 **1.5 秒内只执行一次**；上滑/下滑类命令（下一集/上一集/广告/直播）**3 秒内只滑一次，绝不连滑**（另有一道 0.9 秒的手势硬锁）
- **唤醒词不和命令组合**：句子里只要出现唤醒词，就只当唤醒，后面说的一律不解析。
  所以「嗨小白下一集」「小白广告」这种**不会执行任何命令**（命令要分开单独说）。
  说「嗨小白」只会唤醒，也不会被当成命令（曾经它会命中单字“小”→ 把音量一路压到静音）
- 唯一例外：「小白再见 / 再见小白 / 小白拜拜」照旧彻底退出
- 成对命令（大/小、上/下、亮/暗…）**3 秒内不许反着再来一次**（否则本地引擎会把「声音大一点」听成「声音小」）
- **一个字的命令（`停` `大` `小` `亮` `暗`）只在真的有视频/声音在播时才执行**：
  视频停了、或者页面上根本没在放的时候听到一个单字，只会写一条日志、不动屏幕（日志：`听到了「停」，但没执行：现在没有视频/声音在播`）
  （**摇一摇**也是同一个标准：没在播就不动手）
- **单字「放」已经去掉**：太容易在台词里被触发（“放假/放下/放松”…）。要暂停说 `停`/`暂停`，要播放说 `播放`/`继续`/`放着`/`放一下`
- 每条被拦下的都会写进日志，写明拦的原因

## 四、「退出广告 / 退出直播」是怎么做的

视频 App 的界面文字**读不到**（无障碍窗口列表里只有输入法和我们自己的悬浮条），所以全程靠**截屏 + OCR**：

1. **先截图**（Android 11+ 的无障碍截屏，1 秒最多一次，**不需要**「录屏授权」这个弹窗）
   —— 先拍再点，截图不会被暂停图标/暂停那一瞬的画面影响
2. **点一下 (50%,20%)** —— 就是暂停播放（已经在暂停就不点：再点一下反而会把它放起来）
3. OCR 只读**屏幕最下方 20%**，找 `N 秒`（那句「🔒 10 秒后可继续看下一集」）
4. **有秒就等：读到 N 秒 → 等 N−1 秒**。
   为什么减 1 秒：截图 + 识别本身要花掉大半秒，读到的秒数已经过时了；而**宁可晚一秒也不能早**——广告读秒期间是**锁着**的，早滑等于白滑。
5. **上拉之前【再截一张图】确认真的没秒了**（无秒 / 跳秒结束 / 延时到点，都走这一步）：
   - 再截图**还能读到 ≥ 2 秒** → 读秒没走完（或又跳回来了）→ 继续等
   - 再截图**读到 1 秒或读不到** → 确认没秒了 → **这时才上拉**
6. **就上拉这一次，滑完立即收尾**：
   - 用户定稿：广告/退出直播**只能有一次上拉**。上面已经截图比较过、确认无秒字样，所以不再核对、不再补滑（拉多次是不对的）

全过程会在**屏幕下方（读秒行上面一点）显示一条黑色状态条**，每一步都写出来：

```
听到「广告」→ 退出广告
退出广告：先截图，再点 (50%,20%) 暂停播放，然后读读秒
退出广告：截图已拍完，点 (50%,20%) 暂停播放
退出广告：读到读秒 10 秒 → 等 9 秒后上滑
退出广告：按读到的 10 秒（实际等 9 秒）延时结束 → 再截一张图确认没有读秒
退出广告：再截图确认没有读秒了，上滑
退出广告：确认没有读秒 → 上滑（只滑这一次）
退出广告：完成（上滑 1 次）
```

> 为什么不弹 Toast：Toast 一定出现在屏幕最下方，正好盖住读秒那一行，
> 而且会被截屏拍进去、干扰 OCR 判断读秒。所以广告/直播这两条命令改用自己画的状态条：
> 位置在屏幕 79% 处（底边留出 21%）、3 秒后自动消失、不抢触摸。
> 它也没进 OCR 区域（最下方 20%）和像素比对区域（最下方 12%）。

日志会把每一步写清楚：`先截图，再点 (50%,20%) 暂停播放` / `读到读秒 10 秒 → 等 9 秒后上滑` / `延时结束 → 再截一张图确认没有读秒` / `确认没有读秒 → 上滑（只滑这一次）` / `完成（上滑 1 次）`。

**「退出直播」就是「退出广告」＋一个左划**：左划完成后直接调
`startSkipSequence("退出直播")`，和 `startSkipSequence("退出广告")` 是同一条代码路径 ——
左边那一步之后的截图 / 点 (50%,20%) 暂停 / 读秒 / 上拉前再截图确认无秒 / 只上拉一次，
两条命令一模一样。（状态条上会写一行：`退出直播：左划完成 → 接下来和「退出广告」完全一样`）

## 五、参数设置（⚙ 参数设置）

| 参数 | 默认 | 说明 |
|---|---|---|
| 上滑时长 | 300 ms | 越小越"甩"，越大越"拖" |
| 命令冷却 | 2000 ms | 同一句话两次触发的最小间隔 |
| Mic X / Y | 22 / 66（%） | 豆包键盘上麦克风按钮的位置，用 ▶ 测试Mic 自动标定 |
| 点开 Mic 后最多等豆包多久 | 3 秒 | 框里一出现 ≤6 字的短句会立刻收尾，不会真等满 |
| 点 Mic 前延时 | 200 ms | 键盘弹出后再等这么久才点 Mic |

点击位置**不在这里设**，都固定在代码里，想改说一声：
`暂停/播放 (50%,20%)`、`上页 (15%,85%)`、`下页 (85%,85%)`、`上滑 (50%,75%→25%)`。

### 摇一摇（主界面勾选，默认开）

摇一下手机 ＝ **点 (50%,20%) 暂停 → 600ms 后上滑**（等于"暂停并跳过这一段"）。

两道门槛，防误触：

1. **幅度够大、且是连续的摇**：900ms 内要凑够 **3 个超过 2.6g 的峰**才算一次真摇——
   拿手机、放手机、通知振动一下都不会触发；（上一版是“单次 2.2g 就触发”，太松）
2. **只有真的视频/声音在播时才动手**（和单字命令同一个标准）：
   没在播的时候摇了什么都不做，只记一行「摇一摇忽略了：现在没有视频/声音在播」

正在识别命令（框/键盘在身上）时也不响应。

## 六、短剧模式（🎬）与录制模式（🔴）

### 6.1 短剧模式：说「短剧」开关，开了只认这几条 + 自己录的命令

**没有勾选框，和「豆包」一样用语音切换**：说一声 `短剧` ——

- 没开 → **进入短剧模式**；开着 → **退出短剧模式**（恢复接收所有命令）
- 「嗨小白」照旧只是唤醒（什么都不做），不负责退出短剧模式

短剧模式开着时：

| 说的 | 结果 |
|---|---|
| `下集` `下一集` `上翻` `换一集`… | ✓ 接收（上滑） |
| `上集` `上一集` `下翻`… | ✓ 接收（下滑） |
| `广告` `退出广告` `跳过广告`… | ✓ 接收（退出广告流程） |
| `直播` `退出直播` `推出直播` | ✓ 接收（左划 → 和退出广告完全一样） |
| `声音大` `声音大一点` `声音小` `音量小`… | ✓ 接收（调媒体音量；接电话要先把声音弄小） |
| `禁音` `静音` `关声音` | ✓ 接收（**关掉声音**；说「声音」恢复） |
| `声音` `恢复声音` | ✓ 接收（**恢复禁音前的音量**） |
| 自己录的命令（如 `点赞`） | ✓ **照常接收**（录的就是拿来退广告的，见 6.2） |
| `短剧` | ✓ 再说一次就退出短剧模式 |
| `小白再见` `再见小白` `小白拜拜` | ✓ 还是能彻底退出（留的安全阀） |
| `嗨小白` / `小白` | 只是唤醒，不执行动作、也不退出短剧模式 |
| 其他（单字 `大` `小` `亮` `暗` `停`、`打开微信`、`录制`…） | ✗ **一律不接收**：不执行、屏幕下方也不显示，只在日志里写一行为什么不收 |

日志会写成这样（“听到了什么”和“为什么拦”都能看到）：

```
20:11:07  短剧模式已开启：语音「短剧」
20:11:40  听到：「停一下」→ 命令：停 / 继续播放（点 50%,20%）
20:11:40  短剧模式：只听 下集/上集/广告/直播、声音大/小、禁音/声音 和自己录的命令，「停一下」（停 / 继续播放）不接收；说「短剧」可退出短剧模式
20:12:03  短剧模式已关闭：语音「短剧」
```

### 6.2 录制模式：说「录制」→ 做动作 → 双击结束 → 起名保存

**开始**：用语音说 **`录制`**（或主界面点 **🔴 录制动作** →「▶ 现在就开始录制」）。不用先起名字。

**做动作**：直接在要操作的界面做 ——

- **录制时每个动作都会【真的执行】**：浮层把你的触摸接住记下来，
  同时立刻原样转发给系统 —— 点哪点哪、滑哪滑哪，上滑 / 左滑都照常生效
  （转发是一个接一个发的，动作之间会有一点肉眼几乎看不出的延迟）
- 轻点一下 = 记一个「点击位置」；按住拖动 = 记一条「划动」（起点 / 终点 / 划了多久）
- 两个动作之间隔了多久也一起记（最长按 4 秒算）
- 屏幕顶部的浮条实时显示「已记 N 步（点 x / 划 y）」；点错就「撤销上一步」

**结束**：**双击屏幕**（400ms 内点两下）→ 弹出文本框 → 起一个语音命令名 → 「保存」。
（不想双击的话，浮层上面的「完成」按钮也一样；录制中再说一声 `录制` 也等于结束。）

**使用**：以后说这个名字 → 程序按录制的顺序重做这串动作：**按录制间隔，每步额外多等 0.2 秒、相邻动作至少隔 0.3 秒**
（用户要求动作之间要有一定的延时，页面动画才来得及走完）。

注意：

- 名字最好 **2 个字以上**（单字容易被视频台词撞上）；名字会自动进本地识别词表，说得出就听得懂
- 同一个名字再录一次 = **覆盖**旧的那串动作；主界面弹窗里能看到已录的命令（几步 / 约几秒）+ **删除**
- **短剧模式里自己录的命令照常能用**（就是拿来退广告的）
- 一次重放 **3 秒内不会来第二遍**（防本地识别抖一下就连做两次）
- 因为**双击被拿来当结束**，录制过程中没法录「双击点赞」这种动作（要录的话告诉我，改成别的结束方式）

## 七、日志 / 提示在哪看（排错必备）

1. **屏幕下方状态条**：听到命令、以及「退出广告/退出直播」的每一步（读到几秒、上滑第几次、有没有生效）都会写在这上面，3 秒后自动消失
   （**不在命令表里的话不会显示**，但会写进下面两处日志）
2. **通知栏**：常驻通知「手机助手 · 运行中」——不展开能看到**最近 3 条**，展开是**最近 5 条**（带 `HH:mm:ss` 时间）
3. **主界面**：中间那个 **📋 查看最近日志（排错用）** 按钮，弹出可滚动的完整日志

日志不只记录「执行了什么」，也会记录**听到了什么**：

```
14:02:31  听到：「下一集」→ 命令：下一集（上滑）
14:02:31  已执行：下一集
14:02:35  听到：「今天天气不错」→ 不在命令表里（不执行、不提示）
14:02:40  豆包输入框里的字：「广告」
14:02:40  听到：「广告」→ 命令：退出广告
```

出问题把这两处的文字发出来就能定位。

## 八、后台能不能一直跑

**无障碍服务是系统托管的，不是 Activity 的附属**。把 App 从最近任务里划掉，服务通常照样活着。

真正会停掉它的只有三种情况：

| 情况 | 结果 | 处理 |
|---|---|---|
| 被 ROM 省电策略回收 | 服务静默丢失 | 开 ①（电池优化白名单）+ ④（常驻服务） |
| 手动「强行停止」 | 无障碍开关会被系统强制关闭 | 用 App 内的 ⑤ 退出，别用系统那一项 |
| 重启手机 | 无障碍服务由系统自动恢复 | 不用管（`onServiceConnected` 里会自动把常驻服务拉起来） |

本工程做的加固：前台常驻服务（带低优先级通知）、电池优化白名单入口、开机自动恢复、主界面三行状态自检（无障碍 / 常驻服务 / 电池优化，哪项掉了直接点对应按钮）。

### 怎么退出

点 ⑤ 退出会弹确认框：

| 选项 | 做了什么 | 下次怎么恢复 |
|---|---|---|
| **退出** | 写 `enabled=false`、停常驻服务（通知消失）、收窗口。无障碍开关保留 | 重新打开 App 自动恢复 |
| **彻底停用** | 在上面基础上再 `disableSelf()`，把系统里的无障碍开关一起关掉 | 到系统设置里重新开启 |

为什么不全用一个？`disableSelf()` 是单向的——Android 不允许程序自己把无障碍开关**打开**，必须用户手动确认。

## 九、常见问题

- **说「嗨小白」后键盘出来了，但豆包没开始听**：Mic 坐标没对上。点 **▶ 测试Mic**，程序弹出键盘后你手点一下麦克风按钮，它会记住位置。
- **说「亮 / 暗」没反应**：需要主界面 **☀ 允许修改系统设置** 授权（状态栏会写「未允许 ✗ 请点 ☀」）。部分 ROM 开着自动亮度会覆盖，程序会顺手把自动亮度关掉。
- **某条命令老是自己乱触发**：`停/放/大/小/亮/暗` 是单字命令，只有**视频/声音在播**时才会执行（没在播就只记日志、不动屏幕）；`广告/直播` 是两个字的，仍然可能被视频里的话命中。告诉我哪条乱触发，我把它限制得更严。
- **「退出广告」滑了但页面没变**：上拉前会先截图比较确认读秒已经没了才拉；如果日志里写的是「再截图确认还有 N 秒」→ 说明读秒真没走完，它又接着等了（**不会连着拉好几次**）。把日志发我。
- **通知栏没有「运行中」那条**：点 ④。Android 13+ 首次要允许通知权限。
- **生僻名字（红果 / ds / 天鹅）本地识别听不准**：本地模型缺少 `graph/words.txt`，无法做动态语法，现在是自由识别状态。这种情况用豆包模式（勾选那个勾）最准——直接说给它听。
- **装不上 / 闪退**：APK 只含 arm64-v8a，32 位老机器装不上。

## 十、自己编译

### 云端（推荐，本地不用装任何东西）

本工程自带 `.github/workflows/build.yml`：

- **push 到 main** → Actions 自动编译，约 3~4 分钟 → 在该次运行的底部 **Artifacts** 下载 `VolumeSwipe-debug.zip`
- **推 `v*` 标签** → 自动编译**并挂到 Release**，别人可以直接下载

```bash
git tag -f v2.11 && git push origin refs/tags/v2.11 --force
```

> workflow 里没用第三方 `setup-android` action（实测在 runner 上会失败），而是自己用官方 `commandlinetools-linux-11076708_latest.zip` + `sdkmanager` 装 `platforms;android-34` 和 `build-tools;34.0.0`。

### 本地一键（`build_apk.bat`）

双击即可，脚本会自己下载并解压 JDK 17 / Android cmdline-tools / Gradle 8.7（首次约 450 MB，用国内镜像），然后编译并把 `VolumeSwipe-debug.apk` 拷到桌面。

### Android Studio

`File → Open…` 选本工程目录 → 等 Gradle 同步 → 点绿色 ▶ 或 `Build → Build APK(s)`。

## 技术要点一览

| 需求 | 实现 |
|---|---|
| 模拟点击 / 上滑 / 下滑 / 边缘左划 | `AccessibilityService.dispatchGesture()`，失败自动补发一次 |
| 读屏幕下方读秒 | `takeScreenshot()`（Android 11+，无需录屏授权）+ ML Kit 中文 OCR，只读最下方 20% |
| 页面有没有变 | 截屏指纹比对（中间 20%~80% 灰度指纹），以及最下方 12% 的像素比对 |
| 本地语音 | Vosk `vosk-android:0.3.47` + 打进 assets 的中文小模型 |
| 豆包语音输入 | 弹出自己的输入框 → 抢焦点弹键盘 → 点豆包 Mic → 读框里的字 |
| 后台不死 | 前台常驻服务 + 电池优化白名单 + 无障碍服务系统托管 |
| 悬浮命令条 | `TYPE_ACCESSIBILITY_OVERLAY` 窗口，长按拖动记住位置，`FLAG_NOT_TOUCH_MODAL` 不挡下面的 App |
| 短剧模式 | 语音「短剧」切换（`CMD_DRAMA_TOGGLE`）；`AutoService.resolveCmd()`：所有语音路径都走这一个解析入口，只放行 下集/上集/广告/直播 + 声音大/小 + 禁音/声音 + 录制命令（听到唤醒词不退出） |
| 录制 / 回放动作 | 语音「录制」开始（`CMD_RECORD_TOGGLE`）→ 全屏透明浮层接住触摸记成百分比坐标 + 间隔，**同时立即原样转发给系统**（`dispatchGesture` 队列）→ 动作真的生效；**双击屏幕结束**（400ms）→ 悬浮弹框起名保存；重放 = 按录制间隔 + 每步 +0.2s、相邻至少隔 0.3s |
